# 建筑缺陷 OpenCV 分割

先辨明实验模式：

- **纯 OpenCV 基线**：输入仅原图、已冻结 bbox、类别及语义子类型。不能读取模型 mask、RLE、轮廓、多边形或上一轮逐图修补坐标作为分割先验。提供的 `scripts/segment.py` 实现此模式。
- **视觉辅助分割**：查看原图，明确记录助手或用户提供的引导线、轮廓、排除区，使用 `scripts/guided.py` 局部求解。额外几何先验不能称作 bbox 自动推导，也不能与自动基线不加区分地比较。执行前读 [辅助分割规范](references/assisted.md)。
- **模型结果后处理**：仅当任务明确要求时使用模型 mask 作为搜索先验，在原图像素上修边；输出保留原始 mask，并记录方法为 hybrid。不要把后处理收益算作纯 OpenCV 能力。基线脚本不实现后处理；可选自动后处理入口及实测边界见 [API混合后处理](references/api-hybrid.md)。

用户仅要求 bbox+类别实验时默认使用基线；用户要求按原图逐图精修时采用辅助模式，不重复请求已获授权的操作。读取 [方法来源与适用边界](references/source-notes.md) 可了解这一区分的依据。

## 自动基线实施

1. 把已有标注转换成只包含图片路径、实例 id、bbox、class_code 和可选 class_subtype 的输入文件。阅读 [输入输出规范](references/schema.md)。类型含义不清时先确认对象：垃圾、墙面污渍不是同一目标，不能相互替换。D 可用 GroundLitter / WallStain 子类型区分。
2. 选择和记录按类别共享的规则，见 [方法与失效模式](references/methods.md)。同一实验固定参数、随机种子及版本，不根据参考 mask 为单图优化。若需要逐图交互修正，作为单独实验保存。
3. 运行 `python scripts/segment.py --manifest INPUT.json --output NEW_OUTPUT`。依赖 `numpy pillow opencv-python`；使用用户已有 Python 环境即可。脚本不联网、不调用模型、不安装模型权重。输出目录不得覆盖已完成实验。
4. 验证 mask 为原图 W×H 的 0/255 单通道；所有实例像素在自身 bbox 内；RLE 能还原实例文件；实例并集等于总 mask。bbox 采用零基 xyxy、右下端点不包含。多类别重叠允许，并在 JSON 保留独立实例。
5. 查看叠加图，优先复核全幅 bbox、空前景、几乎填满 bbox、颜色接近、墙缝/管线、阴影、深色植物和裸露基材。不要通过填满 bbox 消除空结果。大的区域 ROI 默认缩小处理，细裂缝原分辨率处理，必须保留缩放记录。
6. 需要对比时，在分割完成后单独运行 `python scripts/evaluate.py --reference-manifest REF_MANIFEST.json --results OUTPUT`。此脚本读取参考 mask 只计算一致度，不改变分割。参考若是模型生成或已用 OpenCV 修正的候选标注，不称作独立真值或准确率。

`evaluate.py` 目前适配基线 schema；辅助输出有独立 schema，不能直接假装可接入此评估脚本。辅助验收先核对 RLE、像素、叠加和来源；若需要量化比较，再明确做 schema 适配。

## 辅助精修实施

给每个实例记录 `guide_source`，坐标使用原图像素。裂缝的主干和分支分别画粗引导线；剥落、起皮和空洞使用闭合轮廓；阴影、管线、孔洞或非目标物体用排除区。引导线不是最终mask，闭合轮廓也不是未经求解就直接作为预测的答案。

运行 `python scripts/guided.py --guides GUIDES.json --output NEW_OUTPUT`。路径模式使用暗响应、法向搜索带、动态规划和可变宽度生长；轮廓模式使用三分区初始化的 GrabCut；颜色模式在多边形中结合 HSV 与 RGB 色差，黑斑可用局部亮度区间。一个杂物实例可合并主体轮廓、细带路径和颜色部件，类别仍为杂物。对浅色翘皮或白色析出物，不应默认套暗色阈值。

查看 `guide_overlays/` 和 `overlays/`。若无足够前景/背景种子，停止该实例求解并修正引导，不填满bbox兜底。若触框裁剪丢边，记录问题；基线保持冻结bbox，辅助任务可另行明确修订bbox并保留新版本。每次重算保存新目录和修订原因，迭代上限按任务设定；仍不明确时保留候选并交人工复核。

## 质量与批量策略

空mask、异常前景比例、触框、断裂、多模型分歧只用于筛选难例，不自动判定对错。5000+张可组织为批量初稿→难例筛选→局部精修→人工验收；这是组织方式，不表示本 skill 已集成任何检测模型、SAM服务或自动学习系统。

比较时除分类IoU/Dice，还应考虑裂缝召回、边界距离、辅助次数、引导耗时、复核与返工耗时。当前评估脚本只实现IoU/Dice/像素精确率和召回；边界与骨架指标、人工计时需要另行采集或实现。没有独立真值时不输出准确率结论。

参考一次真实运行的 [结果及失败案例](references/observed-baseline.md)，了解此基线已验证的能力与局限；不要把其中数值当作新数据的预期准确率。

## 输出与结论

基线交付实例/类别/总 mask、原图叠加、bbox 图、含参数和 RLE 的 JSON、单张耗时和质量提示。辅助脚本交付实例/类别/总mask、bbox图、引导叠加、结果叠加、含求解参数与路径宽度的JSON；尚未制作辅助模式对比HTML，如任务需要应补充。OpenCV阶段 token/API费为0，不等于整个视觉辅助流程免费；引导创建与模型调用耗时、token/费用无法取得时记录 null，不用0替代未知。报告视觉检查和数据一致性验证的区别，不声称尺寸正确意味着边界正确。

混合批次逐图标记新生成、沿用或精修来源；不能把沿用旧结果的图片算作本轮新盲测。通用skill不固化历史47张的坐标和样本专用阈值。

作为 API 工作流的 skill/harness 时，可自动做坐标映射、参数路由、候选mask校验、问题标记。需要语义判断的污渍/阴影、涂层/基材及空洞边界不能只靠阈值可靠解决；保留模型或人工复核入口。避免用参考结果反过来调分割再报告同批数据上的提升。
