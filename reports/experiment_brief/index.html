mask表示缺陷具体覆盖哪些像素。叠加图把这些像素标在原图上，方便检查漏选、误选和偏移。

本轮只比较分割效果，不评价检测框和缺陷类型是否判断正确。

02　实验是怎样推进的

  1. 先做小样本试验比较生成效果，发现轮廓偏移和漏检问题。
  2. 固定50张样本和参考标注根据反馈反复修订，统一检测框、类型和实例编号。
  3. 批量运行三种方法先验证小批次，再扩展到50张，随后增加自动精修。
  4. 整理结果并比较同时检查量化指标和典型图片，记录改善与退化。

03　三种方法，各自做什么

OpenCV

一句话理解：根据缺陷类型，在检测框内用颜色、明暗和纹理规则直接筛选缺陷像素，生成mask。

用图像处理规则直接筛选像素。速度快，但容易把阴影、墙缝或背景纹理一起选中。

image2.5

一句话理解：将缺陷附近的局部图像和类型提示交给图像模型生成mask，再按记录的坐标放回原图。

实际使用的 Prompt

提示词要求：只返回黑白mask，按指定类型和位置选出可见缺陷；保持各局部面板的位置与形状，不把检测框直接填白，也不选中完好墙面、阴影或填充区。

展开英文提示词模板与动态字段
Return only a black/white binary mask of this EXACT 1024x1024 input canvas. White=specified visible defect, black=background. This canvas contains {panel_count} separate photo panels in reading order. Process each panel IN PLACE independently; do not combine, move, resize, extend or reconnect panels. All magenta padding MUST be black. Target class: {class_code} {class_description}. Target region coordinates on this submitted canvas: {target_bbox_canvas_list}. Follow actual visible defect boundaries; never fill rectangles. {optional_faint_tail}Do not select intact light wall, shadows or padding. No labels, margins, illustrations or text. Target ID: {target_id}. {optional_subtype_instruction}

上方是代码拼接逻辑的模板化展示，花括号会被每次请求的实际值替换，不是原样发送。

  • panel_count：画布中局部面板的数量；target_bbox_canvas_list：目标在上传画布中的坐标，不是原图坐标。
  • class_code / class_description：缺陷类型及英文定义；target_id：实例编号。例如裂缝C使用 visible linear crack at actual width; exclude joints and shadows。
  • optional_faint_tail：仅R、T、L类保留 Keep faint tail only where visibly discolored. ，其他类不添加。
  • optional_subtype_instruction：地面垃圾增加 Select ground litter: discarded cloth, bags, masks, hangers and loose rubbish; exclude ground stains and wall dirt.；墙面污渍增加 Select wall staining only; exclude ground litter, shadows and intact wall.；未指定这两种子类型时不添加。

依据 local_crop_trial.py 与 batch_local.py 的提示词拼接逻辑整理，并核对已保存的 geometry.json 请求记录。提示词约束不能保证生成轮廓完全对齐。

让模型一次关注一个目标。局部裁剪有助于看清缺陷，但模型生成的轮廓仍可能偏移。

image2.5＋OpenCV

一句话理解：以API生成的mask为初稿，结合原图像素进行局部精修，若候选结果触发异常规则则保留初稿。

候选结果异常：如何判断？

以API原mask为比较对象，以下任一条件触发时，回退到原API结果。

检查项触发回退的条件
空结果候选mask没有任何前景像素。
面积变化过大候选面积 ÷ API原mask面积 < 0.35 或 > 2.50。
与初稿分歧过大候选mask与API原mask的 IoU < 0.10。
求解失败精修求解出现异常，例如有效前景／背景种子不足。

面积比恰好为0.35或2.50、IoU恰好为0.10时，不触发对应回退条件。若API原mask本身为空，直接保留空初稿，不进入精修。

注意：这里的IoU比较“候选与API初稿”，不是与参考标注比较。阈值是本次程序的保护规则，不是质量合格线，也不是已验证的最优参数。裂缝对齐等人工复核提示不单独触发回退。

尝试让已有mask更贴合原图。如果初稿漏掉大片区域，精修也不一定能找回来。

这些时间应该怎样理解？

OpenCV的46.8秒是一次运行的实际经过时间；API的109.1分钟是152次请求任务耗时相加，包含重试及单次结果处理，不是从启动到完成的实际等待时长。并发和多轮重试间隔会影响实际等待时间，因此不能直接计算提速倍数。

这些费用包含什么？

¥5.15是已知API费用的估算部分，并非平台实扣总账单。失败请求费用未知不能当作免费；上述API时间与费用均不含两项历史复用结果的原始请求，以及更早舍弃的试验。

OpenCV无需API费用；在已有API结果上做精修，本次只额外增加约59秒的处理记录，不增加API费用。

不包含人工复核、算法开发、电脑／电力成本及报告整理。API实扣金额和整批实际经过时间未完整记录。数据来自历史运行，不是新一轮测速或当前报价。
